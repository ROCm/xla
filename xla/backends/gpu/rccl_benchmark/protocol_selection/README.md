# `protocol_selection/` - LL, LL128 and Simple boundaries

**Status: not implemented.** This file describes what belongs here.

## The mechanism

RCCL picks one of three wire protocols per collective - `LL`, `LL128`,
`Simple` - by comparing the transfer size against a per-collective range table
(`rccl/src/graph/tuning.cc`, `rcclTuningModel[].llProtoRanges`). Each protocol
is a different device implementation with its own buffering and its own
synchronization, so crossing a boundary swaps the code that moves the data.

The table is selected by architecture:
`rcclGetTuningIndexForArch` maps gfx950 to model 6, gfx942 to model 5, most
others to 0. **The thresholds differ between models**, so a size that lands on
one side of a boundary on one part lands on the other side elsewhere.

For gfx950 (model 6), in bytes:

| Collective    | LL             | LL128                 | Simple    |
| ------------- | -------------- | --------------------- | --------- |
| ReduceScatter | [0, 64 KiB)    | [64 KiB, 8 MiB)       | >= 8 MiB  |
| AllGather     | [0, 64 KiB)    | [64 KiB, 8 MiB)       | >= 8 MiB  |
| AllReduce     | [0, 256 KiB)   | [256 KiB, 70640910)   | >= 70640910 |
| Reduce        | [0, 16383)     | [16383, 16 MiB)       | >= 16 MiB |
| Broadcast     | [0, 2048)      | [2048, 16 MiB)        | >= 16 MiB |

AllReduce's LL bound is 256 KiB in model 6 and 1 MiB in model 7, which is the
clearest illustration of why these numbers are generated by
`extract_thresholds.py` rather than written into cases.

## Why XLA reaches it

By size alone, with no special configuration: XLA emits all five collectives
across the whole range. Sizes that a combiner produced land wherever they land,
which is exactly why the boundaries need deliberate coverage rather than
whatever a workload happened to hit.

## Planned cases

- Each collective at `{threshold - 1, threshold, threshold + 1}` for both of its
  boundaries, per-rank size scaled so the compared quantity is the one the
  library actually tests.
- Both architectures that ship distinct tables (gfx950 model 6, gfx942 model 5),
  since a case correct for one is silently off-boundary for the other.
- `RCCL_LL128_FORCE_ENABLE` as an additional lane, never as a replacement for
  the default-selection cases.
- Correctness only at first. Protocol boundaries are also where per-size
  performance cliffs appear, which belongs in `perf_main.cc` here once the
  correctness sweep is stable.
